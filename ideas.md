 Where anchr sits today

  It's a genuinely polished read-only viewer. Almost every gap falls into one of two buckets: things you can't do
  (it never calls anything but ListObjectsV2/GetObject/presign), or things you can't find (no search at all — you
  scroll, or you don't).

  ---

  Tier 1 — the gaps you feel every day

  1. / to filter, and recursive search. This is the biggest one. browser.items is already an in-memory slice you
  sort — a filter string field + a bubbles/textinput gives you incremental fuzzy filtering for free. Then the real
  prize: recursive search, where you drop Delimiter: "/" from ListObjects and stream every key under the prefix
  through a matcher. S3 has no search API, so a TUI that gives you one is a legitimate reason to choose anchr over
  the console.

  2. Downloads that work off macOS. chooseDownloadDest shells to osascript. Your install.sh ships linux/amd64 and
  linux/arm64 tarballs where D silently fails. Replacing the save panel with an in-TUI path prompt (prefilled
  ~/Downloads/<basename>) is both the portability fix and better UX — no GUI modal stealing focus from a terminal
  app.

  3. Real progress instead of the fake bar. renderTransferBar sweeps a block on tickCount — it's indeterminate, but
  you already know item.Size from the listing. Wrap the io.Copy in DownloadObject with a counting writer that sends
  a DownloadProgressMsg via tea.Program.Send, and you get a true percentage + throughput + ETA. Cheap, and it makes
  the app feel twice as fast.

  4. Multi-select. space to mark, renderItem gets a check column, then bulk download / copy keys / (later) delete.
  Standard file-manager muscle memory, and it's a prerequisite for most write ops being pleasant.

  5. ? help overlay. CLAUDE.md flags that statusHints is hand-maintained in parallel with keys.go. A ? modal
  generated by iterating the keyMap kills that whole class of drift.

  ---

  Tier 2 — write operations (viewer → manager)

  Upload, delete, mkdir, rename. But the one that's actually cool:

  Cross-bucket server-side copy. You already hold []*s3client.Client for every configured bucket. Add a dual-pane
  mode (Midnight Commander style — tab between two browsers, F5/c to copy) and implement it with CopyObject, so
  bytes move S3→S3 and never round-trip through the user's laptop. Moving 4 GB between a MinIO dev bucket and a prod
  bucket becomes instant. No S3 TUI does this well, and your architecture is already 80% of the way there.

  Pair write ops with a read_only: true per-bucket config flag so a prod entry physically can't be deleted from.
  That one line of YAML is what makes people comfortable pointing this at real infrastructure.

  ---

  Tier 3 — the genuinely fun stuff

  - Inline image previews. preview.go already does a ranged GET and bails on isBinary. Detect image/* via kindFor,
    fetch the whole object, and emit a kitty-graphics or iTerm2 inline-image escape sequence (with a
    chafa/ANSI-halfblock fallback for everything else). Browsing an image bucket and seeing the thumbnails is the
    feature that sells the screenshot in your README.
  - Edit in place. Preview → e → dump to a temp file → $EDITOR → on exit, PutObject if the bytes changed. For anyone
    storing configs or JSON in S3 this is transformative, and it's a small delta on top of preview + upload.
  - Syntax highlighting + JSON pretty-print in the preview (chroma, keyed off kindFor's mime), and o to pipe the
    object to $PAGER/bat for full-file reading beyond the 64 KB cap.
  - du on a prefix. Recursive size rollup with a little bar chart per subfolder. "Why is this bucket 12 TB" is a
    question everyone has and nobody has a good tool for.
  - Object versions. On a versioned bucket, v lists ListObjectVersions for the selected key — diff, download, or
    restore an old version.
  - Glacier restore. You already read StorageClass into S3Item; right now a GLACIER object just errors on download.
    Detect it and offer RestoreObject with a tier picker instead.

  ---

  Tier 4 — onboarding & ergonomics

  - anchr s3://bucket/prefix as an argument, zero config. Right now config.Load hard-fails without a YAML file,
    which is a real wall between "curl the installer" and "see the thing work."
  - profile: field in BucketConfig (config.WithSharedConfigProfile) — SSO users currently have no clean path.
  - Bucket auto-discovery via ListBuckets, so one credential entry populates the whole sidebar instead of
    hand-writing 20 blocks.
  - Listing cache keyed by prefix, so goBack is instant, plus r to force-refresh.
  - Presigned PUT URLs — "send me a file" links, the natural companion to u.

  ---

  If I were picking three

  1. / filter + recursive search — biggest daily-use win, and it's the thing S3 itself can't do.
  2. Cross-platform download with a real progress bar — this is a shipped bug on Linux, not a feature.
  3. Inline image previews — the one that makes people share a screenshot of your tool.
